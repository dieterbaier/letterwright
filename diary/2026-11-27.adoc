== Entscheidungen des Owners

* Vier allgemeine Dokumentbegriffe: document type (gehört dem Host), document
  template (`LetterTemplate`), layout template (`Letterhead`), generated
  document (`Letter`). Ohne deutsche Entsprechungen.
* Der Host wählt für seinen fachlichen Dokumenttyp die Dokumentvorlage und gibt
  sie letterwright direkt vor (doc-03000, „Selecting the Document Template“).
* Das Repository heißt `letterwright`; intern, auch in den Clock-Skills, wird
  nur noch der neue Name verwendet.
* Die allgemeinen Begriffe sind eine bewusste Indirektion. Sie bleiben auf
  Glossar und Systemkontext beschränkt. Eine Umbenennung im Code bräuchte ein
  eigenes ADR, erst wenn letterwright andere Dokumentarten unterstützt.

== Gelernt

* **Eine wörtliche Übersetzung macht eine unscharfe Stelle sichtbar.**
  „Standardschreiben“ stand im Deutschen auch für das erzeugte Schreiben. Mit
  „letter template“ las es sich eindeutig als Vorlage, erst dadurch fiel es im
  Review auf.
* **Eine Entscheidung im PR-Kommentar ist noch nicht dokumentiert.** Die
  Vorlagenauswahl stand zuerst nur im Kommentar. Das zweite Review hat sie in die
  Doku geholt, wo sie auffindbar bleibt.
* **GitHub Pages hat keine Weiterleitung.** Nach dem Umbenennen leiten
  Repository-, Issue- und PR-Links weiter, die alte Pages-URL liefert 404.
* **Ein Worktree mit Submodul lässt sich von `gh pr merge` nicht entfernen.**
  `git worktree remove` verweigert es, nach Prüfung auf Sauberkeit hilft
  `--force`.
