== Entscheidungen des Owners

* Die Typen validieren, die Anwendungsfälle nicht. Javadoc nur für das Warum und
  für den SPI-Vertrag. Die Architekturdoku beschreibt Architektur; Muster stehen
  in der Lösungsstrategie, mit Verweis auf die Quelle.
* Die Zusage „nie eine NullPointerException“ gilt an den Grenzen.
* Die Standardprüfungen von Error Prone bleiben aktiv. Ausnahmen werden einzeln
  begründet; Error Prone ist das Linting des Backends.
* Die Kombination aus Standardschreiben und Bezug wird doppelt geprüft:
  Bezugstyp am Standardschreiben und Standardschreiben in der
  Berechtigungsanfrage (ADR-020).
* Die Berechtigung wird vor dem Veröffentlichungsstatus geprüft. Unberechtigte
  erfahren nicht, ob eine Version veröffentlicht ist.
* Eine aktualisierte Vorschau ersetzt den eigenen Snapshot, und die Laufzeit
  beginnt neu. Ein fremder Snapshot wird wie ein nicht vorhandener behandelt.
* Die Vorschau nutzt die neuesten veröffentlichten Versionen.
* Fachliche Ablehnungen sind Ergebnistypen, `switch` ohne `default`; technische
  Fehler bleiben Ausnahmen.
* Spezifikationen liegen unter `features/<bereich>/`.

== Gelernt

* **Ein Gate braucht einen Nachweis, dass es scheitern kann.** `@NullMarked`
  allein war Dokumentation. Erst die Proben zeigen, dass NullAway eine Verletzung
  erkennt, und erst `RequireExplicitNullMarking` schließt die stille Umgehung.
* **Error Prone fand beim Einführen gleich einen echten Fehler:** einen
  Referenzvergleich in `Versionsfolge`.
* **Die Reihenfolge von Prüfungen kann Informationen preisgeben.** Eine Prüfung,
  die vor der Berechtigung läuft, verrät Unberechtigten Internes. Aufgefallen ist
  das erst durch die Review-Frage und nicht durch einen Test, weil es kein
  Szenario dafür gab.
* **Ein Regressionstest zählt erst, wenn er gegen den alten Code scheitert.** Mit
  der alten Reihenfolge schlugen die vier neuen bzw. geänderten Tests fehl.
* **Ein Abdeckungs-Gate je Modul trifft auch Records ohne Logik.** `usecases-in`
  brauchte einen Test, der die Ergebnisfälle per `switch` unterscheidet.

=== Entscheidungen des Owners

* Ein gelöschtes Schreiben: Eine Wiederholung des Speicherns bekommt „Snapshot
  unbekannt“, auch im gleichzeitigen Pfad. Das PDF der unterlegenen Anfrage wird
  entfernt.
* Logisches Löschen ist ein Zustand im Aggregat `Schreiben`. Eine Übersicht ohne
  Berechtigung ist „nicht erlaubt“. Der Download prüft die Prüfsumme; eine
  Abweichung ist ein technischer Fehler.
* Tests gehören zu ihrer Klasse; Anwendungsfalltests heißen nach der
  Implementierungsklasse. Die Konvention darf allgemein gelten, wenn mit KI
  implementiert wird.
* Je Vorlage höchstens eine veröffentlichte Version; neue Schreiben entstehen mit
  ihr, gespeicherte bleiben unverändert. Die bisherige wird *abgelöst*.
* Beispieldaten pflegt der Vorlagenverwalter an der Vorlagenversion. Das
  Probe-PDF entsteht mit dem veröffentlichten Gegenstück.
* Für das Briefpapier zählt beim Veröffentlichen eines Standardschreibens der
  Prüfzeitpunkt, nicht der Zeitpunkt des Speicherns.

=== Gelernt

* **Bedingtes Schreiben sichert nur das Aggregat, das geschrieben wird.** Beide
  P2-Befunde des Nachmittags betrafen Vorbedingungen an einem anderen Objekt:
  das gelöschte Schreiben hinter einem verbrauchten Snapshot und das Briefpapier
  hinter einem Standardschreiben. Solche Lücken sieht kein Test gegen Attrappen,
  solange niemand ein Szenario dafür schreibt.
* **Ein Wettlauf ist harmlos, wenn sein Ergebnis einer erlaubten Reihenfolge
  gleicht.** Das Argument trug die Entscheidung für den Prüfzeitpunkt und machte
  eine zweite Vorbedingung im Port überflüssig.
* **Invarianten müssen den Lauf der Zeit überstehen.** `Seite` lehnte eine leere
  Seite hinter dem Ende ab; zwischen zwei Abrufen kann aber gelöscht werden.
* **Eine Mutation muss unter `-Werror` kompilieren.** Konstante Bedingungen und
  ungenutzte Variablen bricht der Compiler ab, bevor ein Test läuft. Taugliche
  Mutationen ändern Laufzeitwerte.
* **Erwartete Werte aus dem Produktionsmapper verbergen dessen Fehler.** Nach #65
  erkennen die Adaptertests einen absichtlich eingebauten Abbildungsfehler.
