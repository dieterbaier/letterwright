== Entscheidungen des Owners

* Die Folgekriterien aus #79 stehen als Akzeptanzkriterien in #10.
* #79 wird auf das Ergebnis des Anwendungsfalls begrenzt und schließt mit PR #82.
* Bei mehreren Beans `NachDemSpeichern` gilt die Auswahl von Spring nach den
  üblichen Regeln; bleibt sie mehrdeutig, startet die Anwendung nicht. Vom Agenten
  vorgeschlagen, im Convergence Check bestätigt.

== Gelernt

* **Ein Szenario verspricht nur, was sein Brückentest prüft.** „Wird gespeichert
  wie bisher“ hing an einem Test, der nur die Verdrahtung prüft. Was erst eine
  spätere Schicht nachweisen kann, gehört mit Verweis in deren Issue.
* **Ein Akzeptanzkriterium kann an der falschen Schicht hängen.** „Der Snapshot
  bleibt offen“ leistet der Rollback an der äußeren Grenze, nicht der
  Anwendungsfall. Das fiel erst beim Umsetzen auf.
* **Eine Regel über Spring beschreibt man allgemein.** `getIfAvailable()` wählt
  nicht nur über `@Primary`; ein Vertrag, der eine Regel nachbaut, ist schnell zu
  eng.
* **Bei einer Störung der GraphQL-Schnittstelle von GitHub hilft die REST-API.**
  `gh issue edit` scheiterte, `gh api -X PATCH` ging.
