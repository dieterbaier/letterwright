== Phase 0: Architecture (this increment)

arc42 draft, ADRs, quality scenarios, risks; review by the owner.

== Phase 1: Prototype (spike)

Prerequisite: the DOCX references delivered later (Q-PO-004).

. **Clarify fonts first:** font source and free substitute fonts according to
  xref:adr-017-bereitstellung-der-schriften[ADR-017] (Q-PO-010). The prototype checks
  whether both renderers set the same file the same way and how closely the
  substitute fonts match.
. Rebuild real DOCX templates in the template model (single and multi-page).
. Measure against the acceptance criteria from ADR-004: PDF/A (QS-001), PDF/UA (QS-002),
  fidelity (QS-004) and **style fidelity to the DOCX specification (QS-013)**.
. Check the rendered, paginated preview on the multi-page reference letter according to QS-003
  (automatically and with a screen reader).
. Check acceptance with business users.

The result decides whether ADR-003, ADR-004 and ADR-005 are accepted.

== Phase 2: MVP (epic candidates)

. Project skeleton and quality gates (monorepo, Gradle, Vite, CI, coverage, ArchUnit, veraPDF).
. Domain model and ports (letterhead, letter template, versions, letter, SPIs).
. Rendering pipeline (merging, Paged.js preview, PDF/A and PDF/UA generation).
. Letterhead maintenance (editor, DIN 5008 form A/B, private).
. Letter template maintenance (rich text, placeholders, blocks, defaults, letterhead assignment).
. Preview, save, list, download, print, delete.
. Persistence (JDBC, Liquibase, PostgreSQL, MariaDB).
. Example application and integration documentation.

The epics are created as GitHub issues after the review of this architecture.

== Later

Multiple languages, enclosures, DOCX import for text content, object storage adapter.
