= Click Demo of the Example Application
:status: draft
:reviewed: false

Clickable prototype of the wireframes from `../exampleApp.pen`.
It shows the customer path (order form) and the administrator path
(login, orders, letter templates, templates, letterheads).

== Starting the Demo

The demo consists of static HTML files. It needs no server and
no installation, but an internet connection (fonts from Google Fonts,
vehicle images from Unsplash).

[source,bash]
----
open src/docs/wireframes/exampleApp/demo/bestellmaske.html
----

Alternatively, double-click the file in the Finder.

Entry points::
* `bestellmaske.html` – customer path: choose model, choose extras, enter data, order
* `index.html#login` – administrator path

The dark bar at the top switches between the two paths. On the admin pages, a
click into empty space shows the clickable areas.

== Flows

[cols="1,2"]
|===
| Screen | Clickable

| Order form
| Choose model and extras (summary and total price update along),
  edit fields (e-mail is validated), “Bestellung bestätigen” → thank-you page,
  “Anmelden” → admin login

| Thank-you page
| “Zurück zur Bestellmaske”, logo → order form, “Anmelden” → admin login

| Admin login
| “Anmelden” → order list, “Zurück zur Bestellmaske”

| Order list
| every row → order B-1006 (only this one is worked out)

| Order (order confirmation)
| “Abschließen” → delivery order, “Zurück” → order list,
  “Drucken” only shows a notice

| Delivery order
| “Abschließen” → order list, “Drucken” only shows a notice

| Templates for letter templates
| “Bearbeiten” on the order confirmation → edit template; on the
  delivery order only a notice

| Letterheads
| “Bearbeiten” only shows a notice (screen not designed yet)

| Edit template (order confirmation)
| Select a letterhead and edit the letter body (real input fields on top of
  the image), “Speichern” keeps the state for the browser session,
  “Abbrechen” discards it; both → templates for letter templates

| Administration
| Tabs “Vorlagen für Standardschreiben” / “Briefpapiere”

| All admin pages
| Menu “Bestellungen” / “Administration”, “Abmelden” → admin login
|===

== Files

[cols="1,1,2"]
|===
| File | Kind | Content

| `index.html` | maintained by hand
| Navigation of the admin pages: screens, coordinates of the click areas and
  of the input fields (`fields`) on the “edit template” form

| `bestellmaske-demo.js` | maintained by hand
| Click logic of the order form; finds elements by the layer names from pen.dev
  (`Car – …`, `Extra – …`, `Field – …`, `Summary Card`, `Primary Button`, `Menüpunkt Anmelden`)

| `bestellmaske.html` | exported from pen.dev
| HTML export of the order form, extended with `<script src="bestellmaske-demo.js">`

| `screens/*.png` | exported from pen.dev
| Images of the other screens, file name = node ID in the `.pen` file
|===

The exported files are checked in although they are generated: the export
needs the pen.dev app and cannot be repeated in the pipeline.

== Updating the Demo after Design Changes

The design in `../exampleApp.pen` is the source. After changes there:

. *Admin pages, login, thank-you page:* export the screen as PNG (scale 1)
  to `screens/<node ID>.png`. If buttons have moved, adjust the
  coordinates `[x, y, width, height]` in `index.html`.
. *Order form:* export as “HTML + CSS” to `bestellmaske.html`, then
  insert `<script src="bestellmaske-demo.js"></script>` before `</body>` again.
  Do not rename the layer names (see above), otherwise the script no longer
  finds the elements.
. *New screen:* export the PNG and enter it in `index.html` under `screens` with
  its click areas.
. Click through the demo once in the browser.

With an AI agent in pen.dev, the instruction “Update the demo” is enough.

The SVG screenshots of the forms in the parent folder are also exported from
pen.dev (export as SVG) and regenerated on design changes.
