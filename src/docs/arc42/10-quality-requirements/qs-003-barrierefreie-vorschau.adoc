== QS-003: Accessible Preview

=== Status

Proposed.

The response measure is a reviewable target. Treat uncertain values as
assumptions until confirmed.

=== Scenario

[cols="1,3", options="header"]
|===
| Element | Description
| Source | User with a screen reader or without a mouse
| Stimulus | Opens the preview, reads it and triggers save. Triggers print or download for the saved letter.
| Environment | Normal operation in current browsers.
| Artifact | React components preview and list.
| Response | All content is readable, all actions can be reached by keyboard, focus and status messages are announced.
| Response Measure | Automated: 0 axe-core violations of the levels serious and critical in component and E2E tests; all actions can be carried out by keyboard in an E2E test. Manually per release on a multi-page reference letter in the actually paginated DOM with NVDA/Firefox and VoiceOver/Safari: the reading order matches the logical letter order; repeated headers and footers as well as page numbers are not read out as running text; after saving, focus moves to the status message; status messages (saved, error, missing placeholders) are announced. 0 open findings of the checklist.
|===

=== Rationale

Issue #1 requires an accessible preview.

=== Assumptions

* WCAG 2.1 AA is sufficient (no specific requirement from the owner).
* Automated checks (axe-core) detect only part of the barriers; reading order and announcements in the paginated DOM need a manual check.
* Paged.js duplicates running headers and footers per page; they must be hidden from assistive technologies or marked as repetitions.
