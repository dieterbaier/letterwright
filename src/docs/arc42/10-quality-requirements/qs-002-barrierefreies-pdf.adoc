== QS-002: Accessible PDF

=== Status

Proposed.

The response measure is a reviewable target. Treat uncertain values as
assumptions until confirmed.

=== Scenario

[cols="1,3", options="header"]
|===
| Element | Description
| Source | Recipient who uses a screen reader
| Stimulus | Opens a downloaded letter.
| Environment | Normal operation; reference templates in CI.
| Artifact | Generated PDF.
| Response | Reading order, headings, sender and recipient block, tables and images with alternative text are tagged correctly; document language and title are set.
| Response Measure | Automated: 0 veraPDF errors against PDF/UA-1 for all reference PDFs; this includes a set document language. Manual sample per release on at least one single-page and one multi-page reference PDF (e.g. with NVDA and the PDF Accessibility Checker PAC): the reading order matches the logical letter order (sender, address, information block, subject, text, closing, content footer); alternative texts are meaningful in content (no file name, no “image”); a content footer (e.g. opening hours, homepage) is read out exactly once after the letter text; page numbers, decorative elements, identical repetitions of headers and footers as well as fold marks are marked as artifacts; the document title is announced. 0 open findings.
|===

=== Rationale

Issue #1 requires an accessible saved document.

On the footer, the owner decided in the https://github.com/dieterbaier/standardschreiben/pull/47#pullrequestreview-5997431593[review of PR #47]: details such as opening hours and
homepage belong in the reading order once, after the letter text. Until then,
the response measure required headers and footers as artifacts across the board.
openhtmltopdf achieves this only with a post-processing step
(xref:adr-004-rendering-pipeline-fuer-vorschau-und-pdf[ADR-004]).

On the document language, the owner decided after the NVDA sample on the prototype (2026-11-23):
the response measure no longer requires that the language is announced;
NVDA did not announce it in the sample. A manual check of whether the text is read
in the set language cannot tell the difference for a German letter and a
German default voice. That is why only the automated stage checks whether the
language is set: veraPDF reports a missing language as a violation of PDF/UA-1
(counter-check in the prototype with the Word PDF).

=== Assumptions

* The automated check covers only the machine-checkable criteria; a manual sample with a screen reader complements it.
