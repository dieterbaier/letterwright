== QS-004: Fidelity Between Preview and PDF

=== Status

Proposed.

The response measure is a reviewable target. Treat uncertain values as
assumptions until confirmed.

=== Scenario

[cols="1,3", options="header"]
|===
| Element | Description
| Source | User
| Stimulus | Checks the preview and then saves.
| Environment | Normal operation; reference templates with one to three pages in CI.
| Artifact | Rendering pipeline (Paged.js and PDF renderer).
| Response | The saved PDF matches the preview.
| Response Measure | For all reference templates: same page count, same first and last text line per page, position deviation of central building blocks ≤ 1 mm.
|===

=== Rationale

The owner requires that the preview and the final document look the same.

=== Assumptions

* The same embedded fonts in both paths.
* What is measured is the preview as the browser displays it. A print PDF of the
  preview is an aid and proves only part of it.

=== Measurement Status

The prototype from #3 meets the response measure for both reference letters on
the Chrome print PDF of the preview: same page count, same first and last
line per page, at most 0.3 mm deviation. A counter-check shows that the
comparison finds additional pages and lines.

The owner checked the screen display by visual inspection on 2026-11-21:
preview in the browser and PDF at 100 % side by side, no difference visible.
The 1 mm limit cannot be proven this way; a screen pixel measures about
0.26 mm. The exact measurement will be an automated test in #7: after
pagination by Paged.js, it reads the line positions from the browser's DOM,
that is exactly what the screen shows, and compares them with the PDF like the
prototype.
