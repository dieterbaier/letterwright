= Querschnittliche Konzepte

== Bedrohungsmodell

[cols="1,2,2", options="header"]
|===
| Bedrohung | Angriffsweg | Gegenmaßnahme
| Template-Injection | Manipulierte Vorlage führt Code aus | Abgesicherte FreeMarker-Konfiguration, Tests (xref:r-004-template-injection-durch-vorlagen[R-004])
| Unberechtigter Zugriff auf Schreiben | Erratene oder fremde IDs | UUIDs, Berechtigungsprüfung bei jedem Zugriff, 404 statt 403 (xref:qs-009-zugriffsschutz-beim-download[QS-009])
| Cross-Site-Scripting | Platzhalterwerte oder Vorlageninhalt mit Skript | HTML-Escaping als Standard, HTML-Sanitizing des Editor-Inhalts, kein Skript in Vorlagen
| Schadhafte Uploads | Manipulierte Logos (SVG mit Skript) | SVG bereinigen oder nur Rasterformate, Größenlimit
| Datenabfluss über Logs | Personenbezogene Daten im Log | Nur IDs und Versionen loggen
|===

== Sicherheit

Authentifizierung und Autorisierung kommen aus der Spring Security des Hosts. Die
Bibliothek fragt für jede Aktion die `Berechtigungspruefung` des SPI
(xref:adr-016-schnittstelle-zur-host-anwendung[ADR-016]). Aktionen sind
`VORLAGEN_PFLEGEN`, `SCHREIBEN_ERZEUGEN`, `SCHREIBEN_ANSEHEN`,
`SCHREIBEN_HERUNTERLADEN` und `SCHREIBEN_LOESCHEN`; alle außer der Vorlagenpflege
beziehen sich auf einen fachlichen Bezug.

Stellt der Host keine eigene `Berechtigungspruefung` bereit, gilt die
Default-Implementierung des Starters. Sie erlaubt eine Aktion, wenn der angemeldete
Benutzer der angefragte ist und die Authority `ROLE_SSW_<AKTION>` hat, etwa
`ROLE_SSW_SCHREIBEN_ERZEUGEN` (in Spring Security `roles("SSW_SCHREIBEN_ERZEUGEN")`).
Abweichende Authorities setzt der Host mit
`standardschreiben.berechtigung.rollen.<AKTION>`. Den fachlichen Bezug wertet die
Default-Implementierung nicht aus. Wer Schreiben nach Bezug sichtbar machen will
(Q-PO-003), stellt eine eigene Bean bereit; dann tritt die Default-Implementierung
zurück.

Das Verhalten der Default-Implementierung ist als Feature spezifiziert. Die Tests
in `EingebauteBerechtigungspruefungTest` (Modul `spring-boot-starter`) bilden die
Szenarien eins zu eins ab:

== Test

* Domäne und Anwendung: JUnit 5 und Mockito, ohne Spring.
* Adapter: Testcontainers (PostgreSQL, MariaDB), Spring-Slice-Tests.
* Architektur: ArchUnit.
* Rendering: Referenzvorlagen mit veraPDF-Prüfung und Wiedergabetreue-Test.
* Frontend: Vitest, React Testing Library, axe-core; E2E mit Playwright in der Beispielanwendung.
* Gate: 80 % Zeilen- und Zweigabdeckung je Modul (xref:adr-011-qualitaetsgates-im-build[ADR-011]).

== Beobachtbarkeit

Micrometer-Metriken für Dauer von Vorschau und PDF-Erzeugung sowie Anzahl
fehlgeschlagener Konformitätsprüfungen; strukturierte Logs mit Korrelations-ID,
ohne personenbezogene Inhalte. Die Metriken laufen in das Monitoring des Hosts.

== Fehlerbehandlung

Fachliche Fehler (fehlende Berechtigung, abgelaufener Snapshot, nicht konformes
PDF) werden als RFC-9457-Problem-Details an das Frontend gegeben und dort
barrierefrei angezeigt. Technische Fehler brechen das Speichern ab, ohne
Teilergebnisse zu persistieren.

== Barrierefreiheit

Vorlagen tragen Semantik (Überschriften, Listen, Tabellen, Alternativtexte,
Dokumentsprache). Der Editor erzwingt Alternativtexte. Die Vorschau ist HTML mit
Landmarken und Tastaturbedienung; das PDF ist nach PDF/UA-1 getaggt.

== Fachmodell

Die Konventionen für Typen im Fachmodell legt
xref:adr-018-ddd-rollen-und-selbstvalidierung-im-fachmodell[ADR-018] fest:

* **Rolle sichtbar machen.** Jeder Typ trägt eine jMolecules-Annotation:
  `@AggregateRoot`, `@Entity` oder `@ValueObject`. Die Identität eines Aggregats
  oder einer Entität ist mit `@Identity` markiert, am Feld oder an der Methode, die
  sie liefert. Der Name ist der Begriff aus dem
  Glossar, ohne technisches Suffix.
* **Gleichheit.** Aggregate und Entitäten sind finale Klassen, gleich über ihre
  Identität. Value Objects sind Records, Enums oder unveränderliche Klassen mit
  Wertgleichheit.
* **Unveränderlich.** Jeder Zustandswechsel liefert eine neue Instanz.
* **Selbstvalidierung.** Der Konstruktor prüft jedes Pflichtattribut mit
  `Pruefe` aus dem Modul `validierung`. Fehlende oder ungültige Werte ergeben
  `Validierungsfehler` mit dem Attributnamen, fachlich verbotene Schritte
  `UnzulaessigerZustandswechsel`.
* **Erzeugen und Wiederherstellen.** Fabrikmethoden wie `anlegen` erzeugen neue
  Objekte, `wiederherstellen` stellt gespeicherte her. Beide prüfen alle Regeln.
* **Zeit.** Das Modell liest keine Uhr. Methoden, die eine Zeit brauchen,
  bekommen `jetzt` als Parameter.
* **Personenbezogene Daten.** `toString` gibt keinen Datenkontext aus.

== Platzhalter

Syntax `${pfad.zum.wert}`, Defaults, Wiederholungs- und Bedingungsblöcke; fehlende
Werte bleiben sichtbar (xref:adr-008-platzhaltersprache[ADR-008]). Werte liefert der
Host bereits formatiert.
