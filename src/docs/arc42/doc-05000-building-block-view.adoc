= Building Block View

The building block view names, for each building block, the technologies and
libraries it uses. Many modules are still skeletons. A technology in _italics_
is therefore defined by an ADR but not yet included in the build. A building
block with the suffix _(planned)_ is defined by an ADR but not yet created as a
module. What has been tried out in the prototype (`prototyp/`) is described at
xref:bausteine-ebene-2-adapter-rendering[adapter-rendering].

Every building block of the backend is a Gradle module of the same name. Where
it lives in the repository is stated only in `settings.gradle.kts`; the compiler
and ArchUnit enforce the module boundaries
(xref:adr-015-durchsetzung-der-modulgrenzen-im-backend[ADR-015]).
The frontend package is the npm workspace under `src/application/frontend`.

The column “Key libraries” names only libraries that implement an architecture
requirement. All dependencies and their versions are in the version catalog
`gradle/libs.versions.toml` and in `package.json`
(xref:adr-009-build-monorepo-und-versionen[ADR-009]). All backend modules use
Java 21 and JSpecify; this is therefore not stated in every row.

| validation | General checks (required value, not empty, not blank, lower bound) with a uniform error contract; knows no other module; the SPI does not use it (xref:adr-018-ddd-rollen-und-selbstvalidierung-im-fachmodell[ADR-018]) | –
| domain-service | Domain services, free of frameworks; at compile time visible only to `usecases-service`; at runtime the starter brings them in transitively (xref:adr-015-durchsetzung-der-modulgrenzen-im-backend[ADR-015]) | –
| usecases-in | Inbound ports: interfaces of the use cases | –
| usecases-out | Outbound ports, implemented only by adapters of the library; among them `SaveCallback`, through which the use case “save letter” reports a newly created letter before the commit (xref:adr-023-speichern-in-einer-transaktion-des-hosts[ADR-023]) | –
| spi | Interface to the host application with its own data types, without dependency on the library; besides `api` the only module the host sees at compile time (xref:adr-016-schnittstelle-zur-host-anwendung[ADR-016]). xref:adr-023-speichern-in-einer-transaktion-des-hosts[ADR-023] adds the optional interface `LetterSaveCallback`: a callback before the shared commit, only for a new letter, with the result `CallbackResult` | –
| api | Java API for the host with its own data types, without dependency on the library: save a letter in the host's transaction (`SaveLetter`) and receive the result as a return value (`SaveResult`). It joins a running transaction and opens one of its own if none is running (Spring `REQUIRED`). Saving is atomic together with further actions of the host only if the host opens the transaction before the call (xref:adr-023-speichern-in-einer-transaktion-des-hosts[ADR-023]) | –
| usecases-service | Implementation of the use cases | –
| adapter-web | Inbound adapter: REST endpoints, error mapping. When saving, the outer boundary of the transaction; if the host's callback rejects, it rolls back explicitly and then reports the reason (xref:adr-023-speichern-in-einer-transaktion-des-hosts[ADR-023]) | _Spring MVC_
| adapter-api | Inbound adapter: implements `api`, calls the use cases and maps between API types and the domain model. Controls the transaction with `REQUIRED` itself through a `TransactionTemplate`, not through a proxy; a business rejection returns normally and does not mark the transaction as rollback-only (xref:adr-023-speichern-in-einer-transaktion-des-hosts[ADR-023]) | Spring Transaction
| adapter-rendering | Outbound adapter: merging, HTML sanitizing, font resolution, PDF generation and conformance check; white box in xref:bausteine-ebene-2-adapter-rendering[level 2] | _Apache FreeMarker, jsoup, openhtmltopdf, Apache PDFBox and FontBox, veraPDF_, free OFL substitute fonts
| adapter-persistence-jdbc | Outbound adapter: repositories, DocumentStore, Liquibase changelog | _Spring JDBC, Liquibase_ (xref:adr-006-datenbankagnostische-persistenz[ADR-006])
| adapter-host | Outbound adapter: implements the ports `PlaceholderDataSource`, `Permissions` and `DeletionRules`, calls the host's SPI implementations and maps between SPI types and the domain model. If the host returns `null` or invalid values, it reports `HostContractViolated`. With xref:adr-023-speichern-in-einer-transaktion-des-hosts[ADR-023], `HostSaveCallback` implements the port `SaveCallback` and calls the optional callback `LetterSaveCallback`; without a callback from the host it accepts every letter | –
| spring-boot-starter | Auto-configuration `LetterwrightAutoConfiguration`, default adapters, default `AuthorizationCheck` based on Spring Security (steps back as soon as the host provides a bean of its own); exports only `spi` and, with xref:adr-023-speichern-in-einer-transaktion-des-hosts[ADR-023], `api`; `adapter-api` stays internal. It does not yet wire a bean for `api.SaveLetter`, because the use cases themselves are not wired yet (#10). It wires the port `SaveCallback` with the host's callback `LetterSaveCallback` if there is one. If `PlaceholderDataProvider` or `DeletionPolicy` is missing, the context does not start | Spring Boot Autoconfigure, _Spring Security_
| Frontend package | Preview, list, editor. The preview is to be accessible (xref:qs-003-barrierefreie-vorschau[QS-003]); the evidence is still open in #3 (VoiceOver at page change, reflow at 200 %, individual criteria with NVDA). | React, TypeScript, Vite, UnoCSS (xref:adr-013-styling-der-frontend-komponenten[ADR-013]), _Paged.js_ (xref:adr-004-rendering-pipeline-fuer-vorschau-und-pdf[ADR-004]), _ProseMirror/TipTap_ (xref:adr-003-vorlagenformat-fuer-fachanwender[ADR-003])
|===

Crosscutting, without a building block of its own:

* *Backend build and tests:* Gradle with Kotlin DSL and version catalog
  `gradle/libs.versions.toml`, versions via the Spring Boot BOM
  (xref:adr-009-build-monorepo-und-versionen[ADR-009]); JUnit 5, Mockito, AssertJ,
  JaCoCo as coverage gate (xref:adr-011-qualitaetsgates-im-build[ADR-011]);
  ArchUnit in the module `architecture-tests`
  (xref:adr-015-durchsetzung-der-modulgrenzen-im-backend[ADR-015]); Error Prone
  as linter, with NullAway for the null contract
  (xref:adr-011-qualitaetsgates-im-build[ADR-011],
  xref:adr-019-validierung-in-den-typen-und-null-vertrag[ADR-019]); in the module
  `host-contract-test` the evidence that a host with the starter sees only the SPI
  and the Java API at compile time (xref:adr-016-schnittstelle-zur-host-anwendung[ADR-016],
  xref:adr-023-speichern-in-einer-transaktion-des-hosts[ADR-023]); for
  persistence _Testcontainers_ with PostgreSQL and MariaDB.
* *Frontend build and tests:* npm workspaces, Vitest with V8 coverage, React
  Testing Library, jsdom, axe-core, ESLint
  (xref:adr-010-frontend-tests-mit-vitest[ADR-010]); _Playwright_ for E2E tests
  in the example application.

=== adapter-rendering (White Box)

The implementations in `adapter-rendering` are the core of the tool: here,
preview HTML and PDF are created from template versions and the data context
(xref:adr-004-rendering-pipeline-fuer-vorschau-und-pdf[ADR-004]). The module
knows only `usecases-out` and implements two ports: `Renderer` and
`ConformanceChecker` (xref:adr-002-hexagonale-architektur-und-ports[ADR-002]).

The decomposition is a draft. It follows the throwaway prototype from #3
(`prototyp/README.adoc`), whose code is not taken over. The subpackages
are a proposal until epic #7 implements the module.

Preview and PDF are created from the same sanitized HTML. The preview gets
only additions in the head that do not change the layout; it is paginated in
the browser with Paged.js in the preview component of the frontend
(xref:adr-014-isolation-der-vorschau-im-iframe[ADR-014]). `usecases-service`
calls the conformance check through the port, not the rendering control, and
it does so in two places: before every saving of a letter, and when a template
version is published, for a proof PDF with sample data. The check is
mandatory. Without a checker, the host's application context does not start;
if the PDF is not conformant or the check cannot be run, nothing is saved
(xref:adr-005-pdfa-und-barrierefreiheit[ADR-005], section Decision).

[cols="2,4,3,3,3", options="header"]
|===
| Building block | Responsibility | Interface | Technology and libraries | Location (proposal)

| Rendering control
| Runs the steps for preview and PDF in a fixed order. Aborts
  if a step fails; nothing is silently repaired.
| Implements `Renderer` from `usecases-out`
| Java 21
| `…rendering`

| Merging
| Merges letterhead, letter template and data context in two passes into
  one complete HTML document with Paged Media CSS. Escapes
  placeholder values; missing values appear visibly as placeholders.
| Internal: template versions and data context in, HTML out
| Apache FreeMarker with hardened configuration
  (xref:adr-008-platzhaltersprache[ADR-008])
| `…rendering.merge`

| HTML sanitizing
| Sanitizes the merged document according to an allowlist: elements, attributes,
  URL schemes and CSS. Reports every removal as a finding. Outputs well-formed
  XHTML without additional whitespace, because openhtmltopdf needs XML.
| Internal: HTML in, XHTML and findings out
| jsoup (xref:adr-014-isolation-der-vorschau-im-iframe[ADR-014])
| `…rendering.sanitization`

| Font resolution
| Resolves every font family of the template to a file in a fixed order:
  host folder, otherwise substitute font from the mapping table, otherwise
  default font. Reads family, weight and style from the file, not from the
  file name. Reports every substituted family.
| Internal: family in, font file out; reads the configured font folder
| Apache FontBox (xref:adr-017-bereitstellung-der-schriften[ADR-017])
| `…rendering.fonts`

| Substitute fonts
| Free substitute fonts, one free default font and the mapping table.
  No licensed fonts.
| Classpath resources
| Liberation Sans 2.1.5 for Arial, PT Sans Narrow for Arial Narrow, others
  according to ADR-017; all SIL OFL 1.1
| Resources of the module

| Preview preparation
| Adds to the sanitized HTML a Content Security Policy, the fonts as
  `@font-face` and a screen rendering of the pages.
| Internal: XHTML in, preview HTML out; goes via `Renderer` to `adapter-web`
| Java 21; CSP with SHA-256 hash for the Paged.js script
| `…rendering.preview`

| PDF generation
| Renders the sanitized XHTML into a PDF/A-2b with PDF/UA-1 tagging and embeds
  the resolved fonts. Runs in the host's JVM, without an external
  process.
| Internal: XHTML and fonts in, PDF out
| openhtmltopdf with PDFBox backend (xref:adr-004-rendering-pipeline-fuer-vorschau-und-pdf[ADR-004])
| `…rendering.pdf`

| PDF post-processing
| Tags the content footer, which openhtmltopdf outputs as an artifact, as
  readable content: the two text blocks of the first page, opening hours and
  homepage, each once after the letter text. Checks on every generation that exactly the footer texts from the HTML
  are at the end of the structure tree in this order; otherwise it aborts.
  Page numbers, decoration and identical repetitions stay artifacts.
  Accepted by the owner provided the fallback is documented (review of
  PR #47, adoption into QS-002 via #3).
| Internal: PDF in, PDF out
| Apache PDFBox
| `…rendering.pdf`

| Conformance check
| Checks a PDF against PDF/A-2b and PDF/UA-1, before every saving and when
  a template version is published. Default checker that the starter
  configures automatically; without a checker the host does not start (fail-fast); if
  the PDF is not conformant or the check cannot be run, nothing is saved
  (fail-closed).
| Implements `ConformanceChecker` from `usecases-out`
| veraPDF library with Greenfield model (xref:adr-005-pdfa-und-barrierefreiheit[ADR-005])
| `…rendering.conformance`
|===

==== Open Points

* *PDF post-processing:* the owner accepted the step in the review of PR #47.
  The footer semantics are not yet adopted into QS-002, whose response measure
  so far requires footers as artifacts (#3). Fallback if the evidence breaks:
  the footer as a regular, tagged block in the letter layout; a changed
  placement needs acceptance according to QS-013. The step must be rechecked
  with every update of openhtmltopdf (R-003).
* *Findings of the sanitizing:* template maintenance needs them when saving
  (reject, accept anyway, sanitize; #8, #9). Even after “accept anyway”, the
  pipeline sanitizes before every output. Through which port the findings
  reach the core is open.
* *Fonts for the preview:* whether they come embedded as a `data:` URI or from
  the resource endpoint in `adapter-web` is open (ADR-014). In the second case
  `adapter-web` needs the resolved files through a port.
* *Paged.js in the iframe:* in the prototype the backend inserts the script
  inline. Whether in the product the preview preparation or the preview
  component brings it in is open. In both cases the CSP must know the hash.
* *Chromium (option 2 from ADR-004):* would replace the PDF generation. The
  owner has deferred the evaluation (review of PR #47). It comes back into
  consideration if the PDF/UA sample shows a problem that openhtmltopdf and
  PDFBox do not solve reliably (#3).
