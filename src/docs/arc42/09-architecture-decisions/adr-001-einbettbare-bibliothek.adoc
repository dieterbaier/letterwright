== ADR-001: letterwright as an embeddable library

=== Status

Proposed.

This ADR was created with AI assistance. It counts as an architecture decision
only once the responsible owner has reviewed and accepted it.

=== Decision

We propose to ship letterwright as an **embeddable library**:

* Backend: a **Spring Boot starter** with its modules. It runs in the host
  application, uses the host's database, transactions and Spring Security, and
  provides REST endpoints under a configurable path.
* Frontend: an **npm package with React components**. The host application
  embeds them in its user interface, and they work against these REST
  endpoints.

=== Context

Issue #1 asks for a package that is integrated into existing applications. The
domain data comes from a Spring Boot backend, which also persists the letters.
The owner confirmed variant (a), the library. There is no multi-tenancy and no
volume estimate.

=== Decision Drivers

* Simple integration into existing Spring Boot/React applications.
* No additional operations (deployment, monitoring, network).
* Domain data and security stay in the host application.

=== Considered Options

==== Option 1: Library (Spring Boot starter and npm package)

Runs in the process of the host application. Data access through in-process
ports, security through the host's Spring Security. Drawback: the library is
bound to the technology stack and the Spring Boot major version of the host.

==== Option 2: Standalone service with REST API and its own database

Independently deployable and decoupled in technology. However, the host must
deliver domain data over the network, pass identities through and operate one
more service.

==== Option 3: Frontend package only (rendering in the browser)

No backend part. However, it contradicts the requirement to persist in the
backend, and it makes PDF/A-conformant, reproducible generation harder.

=== Consequences

==== Positive

* No additional runtime component; transactions with host data are possible.
* Authorization through the host's existing Spring Security.

==== Negative

* Compatibility with the host's Java, Spring Boot and React versions must be
  actively maintained.
* Heavy dependencies of the library (e.g. PDF rendering) end up in the host
  artifact.

==== Neutral or Follow-Up

* ADR-002 defines the ports between library and host.
* ADR-009 defines the supported versions.
