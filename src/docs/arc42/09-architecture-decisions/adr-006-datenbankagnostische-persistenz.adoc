[[adr-006-datenbankagnostische-persistenz]]
== ADR-006: Database-agnostic persistence with JDBC and Liquibase

=== Status

Proposed.

This ADR was created with AI assistance. It counts as an architecture decision
only once the responsible owner has reviewed and accepted it.

=== Decision

We propose:

* Persistence adapters based on **Spring JDBC** (`JdbcClient`), not JPA. This
  way the library registers no entities in the host's `EntityManager`.
* Schema through a **Liquibase changelog** with portable Liquibase types, as a
  file that the host includes in its master changelog. Optionally the starter
  runs it itself.
* **Configurable table prefix** (default `lw_`) to avoid name conflicts.
* PDFs as **BLOBs** behind the port `DocumentStore`; an object storage adapter
  can follow later.
* **Supported databases** in the MVP: PostgreSQL and MariaDB/MySQL, both
  tested with Testcontainers in CI. H2 only for fast tests.

=== Context

The owner wants database agnosticism, Liquibase and BLOB storage with a port
for a later object storage. There is no volume estimate. The library runs in
the database of the host application.

=== Decision Drivers

* Database agnosticism.
* No side effects on the host's persistence configuration.
* Simple integration of the schema through Liquibase.

=== Considered Options

==== Option 1: Spring JDBC and Liquibase

Explicit SQL over a few tables, full control over BLOB streaming, no conflicts
with the host's persistence unit. Somewhat more mapping code.

==== Option 2: JPA (Hibernate) and Liquibase

Familiar, less mapping code. Entities must be scanned in the host; conflicts
with the host's Hibernate settings are possible; BLOB handling depends on the
dialect.

==== Option 3: Spring Data JDBC and Liquibase

Aggregate-oriented and close to DDD, but its own conventions (naming strategy,
repositories) can collide with the host configuration.

=== Consequences

==== Positive

* The library can be combined with hosts with and without JPA.
* The storage location of the PDFs can change later without a change to the
  domain.

==== Negative

* Mapping code must be tested (counts towards test coverage).

==== Neutral or Follow-Up

* Extend the list of supported databases if a host requires Oracle or SQL Server.
