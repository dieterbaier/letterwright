[[adr-012-distribution-ueber-github-packages]]
== ADR-012: Distribution über GitHub Packages

=== Status

Vorgeschlagen (proposed).

Dieser ADR ist KI-gestützt entstanden. Er gilt erst als Architekturentscheidung,
wenn der verantwortliche Owner ihn geprüft und akzeptiert hat.

=== Entscheidung

Wir schlagen vor, Releases über **GitHub Packages** zu veröffentlichen (Maven-Registry
und npm-Registry), ausgelöst durch Git-Tags in GitHub Actions. Lizenz bleibt **MIT**.

Antwort auf die Frage des Owners: Die Wahl ist **nicht kriegsentscheidend**. Sie
betrifft weder Architektur noch Code, nur Build-Konfiguration und die Dokumentation
für Konsumenten, und kann jederzeit geändert werden.

=== Kontext

Der Owner wünscht GitHub Packages, kann Vor- und Nachteile aber nicht einschätzen.

=== Entscheidungstreiber

* Geringer Einrichtungsaufwand.
* Einfacher Zugang für Konsumenten.
* Später änderbar.

=== Betrachtete Optionen

==== Option 1: GitHub Packages

Vorteile: integriert in das Repository und GitHub Actions, keine zusätzliche Registrierung.
Nachteil: Konsumenten brauchen auch für öffentliche Pakete ein GitHub-Token mit
`read:packages` in ihrer Maven- bzw. npm-Konfiguration.

==== Option 2: Maven Central und npmjs.org

Vorteile: ohne Token nutzbar, Standard für Open Source. Nachteile: Namespace-
Verifizierung, Signierung (GPG) und Registrierung erforderlich, mehr Einrichtungsaufwand.

==== Option 3: Kein Publishing, Einbindung als Git-Submodule oder Quellcode

Kein Registry-Aufwand. Für Konsumenten unüblich und schwer versionierbar.

=== Pugh-Matrix

`+1` steht für bessere Unterstützung, `0` für neutral, `-1` für schwächere
Unterstützung und `?` für eine Bewertung, die eine menschliche Prüfung oder
einen Prototyp braucht. Enthält eine Spalte ein `?`, ist ihre Summe ebenfalls `?`.

[.pugh-matrix]
[cols="2,1,1,1", options="header"]
|===
| Kriterium | Option 1 | Option 2 | Option 3
| Geringer Einrichtungsaufwand | +1 | -1 | +1
| Einfacher Zugang für Konsumenten | -1 | +1 | -1
| Später änderbar | +1 | +1 | 0
s| Summe s| +1 s| +1 s| 0
|===

=== Konsequenzen

==== Positiv

* Release-Pipeline mit wenig Aufwand aufsetzbar.

==== Negativ

* Konsumenten müssen ein Token konfigurieren (R-008).

==== Neutral oder Folgearbeiten

* Bei externer Nutzung Maven Central und npmjs.org erneut bewerten.
