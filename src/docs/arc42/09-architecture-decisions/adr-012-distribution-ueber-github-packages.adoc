== ADR-012: Distribution through GitHub Packages

=== Status

Proposed.

This ADR was created with AI assistance. It counts as an architecture decision
only once the responsible owner has reviewed and accepted it.

=== Decision

We propose to publish releases through **GitHub Packages** (Maven registry
and npm registry), triggered by Git tags in GitHub Actions. The license stays **MIT**.

Answer to the owner's question: the choice is **not make-or-break**. It
affects neither architecture nor code, only the build configuration and the documentation
for consumers, and can be changed at any time.

=== Context

The owner wants GitHub Packages, but cannot judge the advantages and disadvantages.

=== Decision Drivers

* Low setup effort.
* Easy access for consumers.
* Changeable later.

=== Considered Options

==== Option 1: GitHub Packages

Advantages: integrated into the repository and GitHub Actions, no additional registration.
Disadvantage: consumers need a GitHub token with `read:packages` in their Maven or
npm configuration, even for public packages.

==== Option 2: Maven Central and npmjs.org

Advantages: usable without a token, the standard for open source. Disadvantages: namespace
verification, signing (GPG) and registration required, more setup effort.

==== Option 3: No publishing, inclusion as a Git submodule or source code

No registry effort. Unusual for consumers and hard to version.

=== Pugh Matrix

=== Consequences

==== Positive

* A release pipeline can be set up with little effort.

==== Negative

* Consumers have to configure a token (R-008).

==== Neutral or Follow-Up

* With external use, assess Maven Central and npmjs.org again.
