[[adr-014-isolation-der-vorschau-im-iframe]]
== ADR-014: Isolating the preview in an iframe

=== Status

Proposed.

This ADR was created with AI assistance. It counts as an architecture decision
only once the responsible owner has reviewed and accepted it. Acceptance
requires that the prototype (#3) meets the test criteria below.

=== Decision

We propose:

* The preview component shows the letter in an **`iframe`**. The HTML from the
  rendering pipeline (xref:adr-004-rendering-pipeline-fuer-vorschau-und-pdf[ADR-004])
  is loaded as a separate document and **paginated with Paged.js in the iframe**.
* Inside the iframe only the styles of the letter apply, that is, those of the
  DOCX specification (QS-013). Neither the host's CSS nor the library's styles
  and tokens (xref:adr-013-styling-der-frontend-komponenten[ADR-013]) reach
  into it.
* **Controls and status messages** (notice, “Aktualisieren”, save, messages)
  sit **outside** the iframe in the React component. They follow ADR-013.

==== Security

The `sandbox` attribute alone does not prevent scripts from template content:
`allow-scripts` allows all scripts in the frame. Protection therefore consists
of several layers:

* **Sandbox without same origin:** The starting point for the prototype is
  `sandbox="allow-scripts"` **without** `allow-same-origin`. The document in the
  iframe gets its own opaque origin and has no access to the host's DOM,
  cookies and storage. The combination `allow-scripts allow-same-origin` with
  the same origin is ruled out, because the frame could then lift its own
  sandbox.
* **Sanitization in the backend:** Placeholder values are HTML-escaped during
  merging (xref:adr-008-platzhaltersprache[ADR-008]). In addition, the
  finished HTML is sanitized on the server against an **allowlist** of the
  elements and attributes a letter needs. Removed are scripts, event handlers,
  `javascript:` URLs, embedded objects and frames, and references to external
  resources.
* **Content Security Policy in the iframe:** The document carries a restrictive
  CSP, in particular `script-src` only for the trusted code of Paged.js and the
  start of pagination (via hash or nonce). Fonts and images come only from
  allowed sources, for example embedded or from the library's resource
  endpoint.
* **Communication via `postMessage`:** The iframe reports the height and the
  completion of pagination via `postMessage`. The component accepts only
  messages whose source is its own iframe (`event.source`) and that match a
  fixed schema. The origin does not help here, because it is `null` in the
  sandboxed frame.

==== Accessibility

* The iframe carries a meaningful **`title`** (WCAG technique H64). The
  document in the iframe has its own `<title>`, `lang="de"` and correct
  semantics (headings, paragraphs, address).
* Status messages sit outside the iframe in an `aria-live` region.
  “Aktualisieren” replaces the content without losing focus.
* The bigger risks lie in the **DOM structure that Paged.js generates**:
  reading order, possibly duplicated text, repeated headers and footers, and
  page numbers. Repeated layout parts are hidden from assistive technologies or
  announced in a sensible way.
* The automated check with axe-core must include the **content of the iframe**.
  Because the frame has its own origin, a scan of the host page cannot see
  inside. In the test, axe therefore also runs in the document of the iframe.

==== Test criteria for the prototype

* Keyboard navigation through the host page and the preview without a focus
  trap.
* A screen reader reads the letter once, completely and in a logical order.
  Repeated layout parts do not interfere.
* Zoom up to 200 % and reflow without loss of information.
* Asynchronous update without loss of focus; the status message is announced
  via `aria-live` outside the frame.
* Tested with NVDA with Firefox or Chrome **and** VoiceOver with Safari.
* 0 axe-core violations of the levels serious and critical in the content of
  the iframe.
* The height of the iframe adapts to the pages. Fonts and images load under
  sandbox and CSP. Paged.js paginates under sandbox and CSP.
* A test letter with a script, an event handler and a `javascript:` URL in
  template and data executes no code.

=== Context

ADR-013 defines that the user interface adapts to the host, while the letter in
the preview follows only the central DOCX specification. How the letter is
isolated was open (Q-ARCH-003). The owner prefers an `iframe` because he has
little experience with Shadow DOM (2026-11-15). The review in PR #17 made
security and accessibility more precise.

=== Decision Drivers

Must requirements:

* No host CSS and no inherited properties (font, color, line height) change the
  letter (QS-013).
* Paged.js paginates with the letter's own `@page` rules and fonts, the way PDF
  generation sees the HTML (QS-004).
* The paginated preview is accessible (QS-003).
* Content from templates and data executes no code in the host.

Further criteria: embedding effort and experience in the team.

=== Considered Options

==== Option 1: iframe with sandbox

A separate document with its own CSS context and its own origin. Paged.js works
as in a standalone page; `@page` rules and `@font-face` apply only there.
Costs: synchronizing the height, communication via `postMessage`, axe check in
the frame, checking the focus transition.

==== Option 2: Shadow DOM

Stays in the host's document. Host selectors do not reach inside, but inherited
properties do, as long as they are not reset. `@page` rules apply only at
document level. `@font-face` rules inside a shadow root are not applied in all
browsers; only a declaration in the host's document is safe, where it can
collide with host fonts of the same name. Paged.js reads the document's
stylesheets; support for shadow roots is not documented. Scripts run in the
host's context; there is no security boundary.

==== Option 3: No isolation, only a prefix for the letter's styles

Easiest to embed. Host CSS with higher specificity and inherited properties
change the letter; `@page` rules collide with the host.

=== Evaluation

First the must requirements:

[cols="2,1,1,1", options="header"]
|===
| Must requirement | Option 1 | Option 2 | Option 3
| Protection from host styles (QS-013) | met | only with a reset of all inherited properties | not met
| Pagination with own `@page` rules (QS-004) | met | unproven | not met
| Accessibility (QS-003) | evidence in prototype | evidence in prototype | evidence in prototype
| No code from content in the host | met with sandbox, sanitization, CSP | only with sanitization | only with sanitization
|===

Option 3 does not meet two must requirements and is ruled out. For the
remaining options the Pugh matrix applies, with **option 2 as the reference**.

`+1` means better support, `0` neutral, `-1` weaker support and `?` a rating
that needs human review or a prototype. If a column contains a `?`, its sum is
also `?`.

[.pugh-matrix]

| Protection from host styles | +1 | 0
| Pagination as in the PDF | +1 | 0
| Accessibility | ? | 0
| Security boundary | +1 | 0

Without the accessibility criterion, option 1 would have the sum +3. The
prototype provides the evidence for accessibility.

=== Consequences

==== Positive

* The letter looks the same in every host.
* Paged.js runs in its own document, as the owner has already tried out.
* Content from templates and data has no access to the host.

==== Negative

* The component must adjust the height of the iframe via `postMessage`.
* The backend needs HTML sanitization against an allowlist, which must fit the
  template model.
* In the test, axe-core must additionally run in the frame.
* Fonts and images must be reachable under sandbox and CSP, for example
  embedded or with suitable CORS headers.

==== Neutral or Follow-Up

* The prototype (#3) checks the preview in the iframe against the acceptance
  criteria above and the acceptance criteria from ADR-004.
* The `sandbox` and CSP configuration and the allowlist are given in the result
  of the prototype above.
* Whether the fonts in the product come as a `data:` URI or from the resource
  endpoint in `adapter-web`, and who brings in the Paged.js script, is open
  (building block view, `adapter-rendering`).


=== Result of the prototype

The throwaway prototype from #3 (`prototyp/README.adoc`) defines the
configuration and checks the criteria above.

==== Configuration

* *Sandbox:* `sandbox="allow-scripts"` without `allow-same-origin` and without
  `allow-popups`. Paged.js paginates under it.
* *CSP in the document of the iframe:* `default-src 'none'`. Scripts only via
  SHA-256 hash (Paged.js and its configuration). Fonts and images only as a
  `data:` URI. `style-src` needs `'unsafe-inline'`, because Paged.js creates its
  own `<style>` elements at runtime.
* *`postMessage`:* The iframe reports the height, the page count and clicked
  links. The component checks source and schema.
* *Links* open a new tab (owner, 2026-11-20). A script in the iframe intercepts
  the click and sends the target to the host page. The host page checks the
  scheme (`http`, `https`, `mailto`, `tel`) and opens it with `noopener`. The
  iframe does not navigate. If this does not work, links are not allowed in the
  iframe.

==== Allowlist of the sanitization

The backend sanitizes the fully merged document with jsoup before the PDF and
the preview are created, and reports every removal as a finding.

* *Elements:* the structure and text of a letter (paragraphs, headings, lists,
  tables, `img`, `a`, `address`, `header`, `footer`, `main` and others); in the
  head only `title`, `meta` and `style`. Active and embedding elements are
  dropped together with their content (`script`, `iframe`, `object`, `embed`,
  `svg`, `form`, `base`, `link`). Other unknown elements are unwrapped; their
  text remains.
* *Attributes:* `class`, `id`, `lang`, `dir`, `title`, `role`, `style`, some
  `aria-*` and what each element needs (`img`: `src`, `alt`; `a`: `href`;
  table cells: `colspan`, `rowspan`). Event handlers are thus dropped.
* *URLs:* links only `http`, `https`, `mailto`, `tel` and fragments; images only
  as a `data:` URI. A link without an allowed target becomes text. Control
  characters and whitespace are removed before the check.
* *CSS:* `@import` and `url()` are dropped, except for `data:` images and fonts;
  with `expression()` or `javascript:` the whole style declaration is dropped.
* *Output:* XHTML without pretty-printing, because openhtmltopdf needs
  well-formed XML and extra whitespace shifts the layout.

A test letter with 25 attacks from template and data executes no code in the
preview, loads nothing and does not navigate. The counter-check without
sanitization shows what each layer achieves: the CSP alone blocks all code. It
does not help against `<meta http-equiv="refresh">`; only the sanitization
prevents that.

*Findings in templates* (owner, 2026-11-20 and https://github.com/dieterbaier/standardschreiben/pull/47#pullrequestreview-5997431593[review of PR #47]): Template maintenance does not
sanitize silently. It shows the findings and requires a choice: Ablehnen,
Trotzdem akzeptieren or Bereinigen. “Trotzdem akzeptieren” saves the template
unchanged. Before every output the backend still sanitizes the merged HTML
against the allowlist; the preview and the PDF receive only the sanitized HTML,
the preview additionally under the CSP. Implemented in #8 and #9.

==== Test criteria

[cols="3,1,4", options="header"]
|===
| Criterion | State | Finding
| Keyboard without focus trap | met | The pages sit in a focusable area that scrolls with the arrow keys.
| Screen reader reads once, completely, in logical order | with limitation | VoiceOver/Safari reads letter header, address, information block, subject, body text, footer. At the end of the first page a new entry into the frame is needed. The margin areas are hidden with `aria-hidden`; a hidden copy of the footer is at the end.
| Zoom 200 % and reflow | with limitation | The page is a fixed A4 sheet and scrolls horizontally, also by keyboard (exception for two-dimensional content in WCAG 1.4.10). The owner accepts this.
| Update without loss of focus, `aria-live` | met |
| NVDA and VoiceOver | partial | VoiceOver/Safari tested (owner). NVDA 2026.1.1 with Chrome 157 on the multi-page reference letter (owner, 2026-11-23): reads the letter completely, including the alternative texts. Reading order, page breaks and repetitions are not recorded individually for NVDA.
| axe-core in the iframe | met | 0 violations of the levels serious and critical; moderate “content outside landmarks” remains.
| Height, fonts, images, pagination under sandbox and CSP | met | Fonts in the prototype as a `data:` URI, about 5 MB per document.
| No code from template and data | met | 25 attacks, see above.
|===

Paged.js clones an element that spans a page together with its role. The
letter is therefore a `div` with `role="main"`, and the preview removes the role
from the continuations. VoiceOver reads the letter the same way without a
sandbox, with `src` instead of `srcdoc` and with `allow-same-origin`; the
isolation itself is therefore no obstacle.

Note from the re-review of PR #17: additionally secure messages from the iframe
with a correlation value per preview instance. The prototype checks only source
and schema.

=== Assumptions

* Paged.js runs in an iframe with `sandbox="allow-scripts"` without
  `allow-same-origin` and under a CSP that allows only its code.
* The embedded fonts can be loaded in the iframe the same way as during PDF
  generation.
