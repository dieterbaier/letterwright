== ADR-022: Eine veröffentlichte Version je Vorlage, geprüft mit Beispieldaten

=== Status

Vorgeschlagen (proposed).

Der Owner hat am 2026-11-22 bei #55 die Richtung vorgegeben (siehe Abgeleitet
aus). Der ADR ist KI-gestützt formuliert und wartet auf das Review.

=== Entscheidung

* **Höchstens eine veröffentlichte Version.** Je Briefpapier und je
  Standardschreiben ist höchstens eine Version veröffentlicht. Neue Vorschauen und
  damit neue Schreiben entstehen mit ihr. Gespeicherte Schreiben behalten ihre
  Versionen (xref:adr-007-versionierung-und-unveraenderlichkeit[ADR-007]).
* **Abgelöst.** Wird ein Entwurf veröffentlicht, wechselt die bisher
  veröffentlichte Version in den neuen Zustand *abgelöst*. *Zurückgezogen* heißt
  dagegen: Der Vorlagenverwalter hat die veröffentlichte Version ohne Nachfolger
  zurückgenommen; danach gibt es keine veröffentlichte Version, und eine Vorschau
  ist nicht möglich, bis ein Entwurf veröffentlicht ist. Abgelöste und
  zurückgezogene Versionen bleiben unverändert erhalten.
* **Das Aggregat setzt die Regel durch.** `veroeffentlicheEntwurf` löst die
  bisherige Version im selben Zustandswechsel ab; `zurueckziehen` nimmt die
  veröffentlichte Version zurück. Beim Wiederherstellen lehnt das Modell mehr als
  eine veröffentlichte Version ab
  (xref:adr-018-ddd-rollen-und-selbstvalidierung-im-fachmodell[ADR-018]).
* **Beispieldaten an der Vorlagenversion.** Jede Version trägt neben ihrem Inhalt
  Beispieldaten: Werte für ihre Platzhalter, wie sie der Host formatiert liefern
  würde. Der Vorlagenverwalter pflegt sie im Entwurf zusammen mit dem Inhalt. Ein
  neuer Entwurf übernimmt die Beispieldaten der vorigen Version. Mit dem
  Veröffentlichen werden sie unveränderlich; so bleibt nachvollziehbar, womit eine
  Version geprüft wurde. Die Bibliothek fragt dafür nicht den Host; eine weitere
  Host-Schnittstelle widerspräche
  xref:qs-007-integration-in-host-anwendung[QS-007].
* **Probe-PDF mit dem veröffentlichten Gegenstück.** Vor dem Veröffentlichen
  entsteht ein Probe-PDF und wird mit dem `KonformitaetsPruefer` geprüft, wie vor
  jedem Speichern
  (xref:adr-005-pdfa-und-barrierefreiheit[ADR-005]):
** Ein Standardschreiben wird mit der veröffentlichten Version seines Briefpapiers
   gerendert. Die Daten sind die Beispieldaten beider Versionen; bei gleichem
   Schlüssel gilt die des Standardschreibens. Hat das Briefpapier keine
   veröffentlichte Version, wird nicht veröffentlicht.
** Ein Briefpapier wird mit einem eingebauten Beispielinhalt des Renderers und
   seinen eigenen Beispieldaten gerendert. Andere Standardschreiben, die das
   Briefpapier nutzen, werden nicht mitgeprüft.
* **Fail-closed.** Ist das Probe-PDF nicht konform, bleibt der Entwurf ein Entwurf,
  und der Vorlagenverwalter erhält die Befunde. Lässt sich die Prüfung nicht
  ausführen, wird ebenfalls nicht veröffentlicht.
* **Berechtigung.** Veröffentlichen und Zurückziehen verlangen
  `VorlagenAktion.VEROEFFENTLICHEN`. Die Bibliothek fragt den Host, bevor sie die
  Vorlage lädt.
* **Gleichzeitige Änderungen.** Zwischen Laden und Speichern kann ein anderer
  Vorlagenverwalter den Entwurf ändern oder dieselbe Vorlage veröffentlichen. Das
  Repository ersetzt eine Vorlage deshalb nur, wenn sie seit dem Laden unverändert
  ist; sonst wird nichts gespeichert, und der Benutzer lädt neu. So wird nie ein
  Inhalt veröffentlicht, der nicht geprüft wurde.
* **Für das Gegenstück zählt der Prüfzeitpunkt.** Das bedingte Ersetzen sichert
  nur die Vorlage, die veröffentlicht wird, nicht ihr Briefpapier. Wird das
  Briefpapier während der Prüfung eines Standardschreibens abgelöst oder
  zurückgezogen, wird das Standardschreiben trotzdem veröffentlicht. Das Ergebnis
  gleicht der erlaubten Reihenfolge „erst das Standardschreiben veröffentlichen,
  dann das Briefpapier ändern“:
** Nach einer Ablösung entstehen neue Schreiben mit dem neuen Briefpapier, mit
   dem das Standardschreiben nicht geprüft wurde. Das gilt für jede spätere
   Ablösung ebenso (siehe Konsequenzen). Die Prüfung vor jedem Speichern fängt
   ein nicht konformes PDF ab.
** Nach einem Rückzug entsteht mit dem Standardschreiben keine Vorschau, bis ein
   Briefpapier veröffentlicht ist.

=== Kontext

Das Fachmodell aus #51 ließ mehrere veröffentlichte Versionen je Vorlage zu;
`neuesteVeroeffentlichteVersion()` nahm die mit der höchsten Nummer. ADR-018
ließ offen, ob ältere veröffentlichte Versionen gültig bleiben. ADR-005 verlangt
beim Veröffentlichen ein Probe-PDF mit Beispieldaten, sagt aber nicht, woher
diese kommen. Vorlagen enthalten Platzhalter, die erst mit Werten zeigen, ob das
Ergebnis konform ist, etwa ob ein langer Name das Anschriftfeld sprengt oder ein
Bild ohne Alternativtext bleibt.

=== Entscheidungstreiber

* Eindeutig, mit welcher Version ein neues Schreiben entsteht.
* Ein Fehler in einer gepflegten Vorlage fällt vor dem ersten Speichern auf.
* Keine weitere Schnittstelle, die der Host implementieren muss (QS-007).
* Nachvollziehbar, womit eine veröffentlichte Version geprüft wurde.

=== Betrachtete Optionen

==== Option 1: Eine veröffentlichte Version, Beispieldaten an der Version (gewählt)

Wie oben.

==== Option 2: Mehrere veröffentlichte Versionen, Beispieldaten aus den Platzhaltern

Ältere Versionen bleiben veröffentlicht, bis sie zurückgezogen werden; neue
Schreiben nehmen die neueste. Der Renderer füllt jeden Platzhalter mit einem
Wert aus seinem Namen. Keine Pflege, aber unklar, wozu eine ältere veröffentlichte
Version dient, und ein generierter Wert prüft weder Länge noch realistische
Inhalte.

==== Option 3: Eine veröffentlichte Version, Beispieldaten vom Host

Der Host liefert Beispieldaten je Standardschreiben über eine weitere
SPI-Schnittstelle. Realistisch, aber eine vierte Schnittstelle widerspricht
QS-007, und ein Briefpapier hat keinen Bezug, zu dem der Host Daten kennt.

=== Konsequenzen

==== Positiv

* Für Sachbearbeiter und Vorschau gibt es genau eine gültige Version je Vorlage.
* Abgelöst und zurückgezogen sind unterscheidbar; die Historie zeigt, warum eine
  Version nicht mehr verwendet wird.
* Jede veröffentlichte Version ist mit ihren eigenen Beispieldaten geprüft.

==== Negativ

* Der Vorlagenverwalter pflegt Beispieldaten. Fehlen sie, zeigt das Probe-PDF die
  Platzhalter als fehlend (QS-010) und prüft weniger.
* Ein Briefpapier wird nur mit dem eingebauten Beispielinhalt geprüft; ein
  Standardschreiben, das mit dem neuen Briefpapier nicht mehr konform ist, fällt
  erst beim Speichern auf (fail-closed bleibt).
* Der Port `VorlagenRepository` braucht eine bedingte Ersetzung.

==== Neutral oder Folgearbeiten

* #6: Vorlagen mit Beispieldaten je Version speichern; die bedingte Ersetzung,
  etwa mit einer Revisionsspalte.
* #7: Der Renderer erzeugt das Probe-PDF eines Briefpapiers mit eingebautem
  Beispielinhalt.
* #8 und #9: Der Editor pflegt Beispieldaten zusammen mit dem Entwurf.
