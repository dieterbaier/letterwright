[[adr-022-eine-veroeffentlichte-version-je-vorlage]]
== ADR-022: One published version per template, checked with sample data

=== Status

Accepted on 2026-11-22.

The owner set the direction on 2026-11-22 in #55 (see Derived from). The ADR
was drafted with AI support. The owner accepted it and its five relations on
the same day in the review of PR #68, after he had decided the check time for
the counterpart.

=== Decision

* **At most one published version.** For each letterhead and each letter
  template, at most one version is published. New previews, and therefore new
  letters, are created with it. Stored letters keep their versions
  (xref:adr-007-versionierung-und-unveraenderlichkeit[ADR-007]).
* **Superseded.** When a draft is published, the version published so far
  changes to the new state *superseded*. *Withdrawn*, by contrast, means: the
  template manager has taken back the published version without a successor;
  after that there is no published version, and a preview is not possible
  until a draft is published. Superseded and withdrawn versions are kept
  unchanged.
* **The aggregate enforces the rule.** `publishDraft` supersedes the previous
  version in the same state change; `withdraw` takes back the published
  version. On restore, the model rejects more than one published version
  (xref:adr-018-ddd-rollen-und-selbstvalidierung-im-fachmodell[ADR-018]).
* **Sample data on the template version.** Besides its content, each version
  carries sample data: values for its placeholders, formatted as the host would
  deliver them. The template manager maintains them in the draft together with
  the content. A new draft takes over the sample data of the previous version.
  On publishing, they become immutable; this keeps it traceable what a version
  was checked with. The library does not ask the host for this; a further host
  interface would contradict
  xref:qs-007-integration-in-host-anwendung[QS-007].
* **Proof PDF with the published counterpart.** Before publishing, a proof PDF
  is created and checked with the `ConformanceChecker`, as before every save
  (xref:adr-005-pdfa-und-barrierefreiheit[ADR-005]):
** A letter template is rendered with the published version of its letterhead.
   The data are the sample data of both versions; for the same key, the value
   of the letter template applies. If the letterhead has no published version,
   nothing is published.
** A letterhead is rendered with a built-in sample content of the renderer and
   its own sample data. Other letter templates that use the letterhead are not
   checked along with it.
* **Fail-closed.** If the proof PDF is not conformant, the draft stays a draft,
  and the template manager receives the findings. If the check cannot be run,
  nothing is published either.
* **Permission.** Publishing and withdrawing require
  `TemplateAction.PUBLISH`. The library asks the host before it loads the
  template.
* **Concurrent changes.** Between loading and saving, another template manager
  can change the draft or publish the same template. The repository therefore
  replaces a template only if it is unchanged since loading; otherwise nothing
  is saved, and the user reloads. This way, content that was not checked is
  never published.
* **For the counterpart, the check time counts.** The conditional replacement
  only secures the template that is being published, not its letterhead. If
  the letterhead is superseded or withdrawn while a letter template is being
  checked, the letter template is published anyway. The result equals the
  permitted order “first publish the letter template, then change the
  letterhead”:
** After a supersession, new letters are created with the new letterhead, with
   which the letter template was not checked. This applies equally to every
   later supersession (see Consequences). The check before every save catches
   a non-conformant PDF.
** After a withdrawal, no preview is created with the letter template until a
   letterhead is published.

=== Context

The domain model from #51 allowed several published versions per template;
`neuesteVeroeffentlichteVersion()` took the one with the highest number.
ADR-018 left open whether older published versions remain valid. ADR-005
requires a proof PDF with sample data when publishing, but does not say where
the data come from. Templates contain placeholders that only show with values
whether the result is conformant, for example whether a long name breaks the
address field or an image remains without alternative text.

=== Decision Drivers

* Unambiguous with which version a new letter is created.
* An error in a maintained template shows up before the first save.
* No further interface that the host must implement (QS-007).
* Traceable what a published version was checked with.

=== Considered Options

==== Option 1: One published version, sample data on the version (chosen)

As above.

==== Option 2: Several published versions, sample data from the placeholders

Older versions stay published until they are withdrawn; new letters take the
latest one. The renderer fills each placeholder with a value derived from its
name. No maintenance, but it is unclear what an older published version is for,
and a generated value checks neither length nor realistic content.

==== Option 3: One published version, sample data from the host

The host delivers sample data per letter template through a further SPI
interface. Realistic, but a fourth interface contradicts QS-007, and a
letterhead has no reference for which the host knows data.

=== Consequences

==== Positive

* For clerks and the preview there is exactly one valid version per template.
* Superseded and withdrawn can be told apart; the history shows why a version
  is no longer used.
* Every published version is checked with its own sample data.

==== Negative

* The template manager maintains sample data. If they are missing, the proof
  PDF shows the placeholders as missing (QS-010) and checks less.
* A letterhead is checked only with the built-in sample content; a letter
  template that is no longer conformant with the new letterhead shows up only
  on saving (fail-closed remains).
* The port `TemplateRepository` needs a conditional replacement.

==== Neutral or Follow-Up

* #6: Store templates with sample data per version; the conditional
  replacement, for example with a revision column.
* #7: The renderer creates the proof PDF of a letterhead with built-in sample
  content.
* #8 and #9: The editor maintains sample data together with the draft.

In the review of PR #68, the owner asked which point in time counts for the
published letterhead if it changes while a letter template is being checked.
On 2026-11-22 he decided: the check time. The port does not check the
