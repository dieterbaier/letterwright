== ADR-020: How the combination of letter template and business reference is checked

=== Status

Accepted on 2026-11-22.

The owner set the direction on 2026-11-22 in #52: reference type on the letter
template **and** the letter template in the authorization request. The ADR was
worded with AI assistance; the owner accepted it and its four relations on the
same day in the review of PR #63, with a corrected order of the checks.

=== Decision

* **A letter template belongs to exactly one reference type,** for example
  `Customer` or `Case`. The reference type is the same string as the type of
  the `BusinessReference` that the host assigns. If the type of the reference
  does not match, the library itself rejects the preview, without asking the
  host.
* **Creation is a separate authorization request.** Besides `ForTemplates` and
  `ForLetter` there is `ForCreation` with user, business reference and letter
  template. `CREATE` is no longer a `LetterAction`. The host can thus determine
  which letter templates are permissible at which entry point (#11), for
  example only payment reminders for customers with an open item.
* **Order.**
  1. Does the letter template exist?
  2. Does its reference type match the reference?
  3. Does the host allow creation (`ForCreation`)?
  4. Do letter template and letterhead have a published version?
  5. Only then does the library request the data context.
+
An unauthorized user thus always gets “not permitted” and does not learn
whether a version is published. Whether the letter template exists and whether
its reference type matches, on the other hand, remains distinguishable for
them; this ADR protects only the publication status. On saving, permission is
requested again with `ForCreation`.
* **Default authorization check.** The starter still maps `ForCreation` to the
  role for creating letters; this decision does not change the configuration.
  At the time of the decision the role was named
  `ROLE_SSW_SCHREIBEN_ERZEUGEN`, since ADR-024 (#84)
  `ROLE_LETTERWRIGHT_LETTERS_CREATE`.
  It does not evaluate the letter template.

=== Context

A clerk reaches a preview through two entry points (#11): from a business
reference, for which they choose a letter template, or from a letter template,
for which they choose a reference. In both cases, letter template and
reference come from the browser and are therefore not trustworthy. Epic #5
requires that the combination is checked on the server before the host
supplies placeholder data. Otherwise the data context of a reference could be
filled into a letter template that is not intended for it, and the host would
have to catch every combination itself.

Until now, the letter template knew no reference, and the
`AuthorizationRequest` for creation did not know the letter template.

=== Decision Drivers

* No data context for an impermissible combination.
* The host should be able to express business rules per entry point.
* A host without rules of its own should need no additional configuration.
* The contract should state at compile time which data a request carries
  (xref:adr-019-validierung-in-den-typen-und-null-vertrag[ADR-019]).

=== Considered Options

==== Option 1: Only the reference type on the letter template

The library checks the type itself; the SPI stays as it is. The host cannot
express finer rules, for example per entry point or per state of the
reference.

==== Option 2: Only the host decides

The request for creation contains the letter template, and the host decides
alone. Every host then also has to implement the obvious rule “payment
reminder only for customers” itself; the default check of the starter would
allow every combination.

==== Option 3: Both (chosen)

The library checks the reference type; the host gets the letter template in a
separate kind of request and can restrict further.

=== Pugh Matrix

`+1` means better support, `0` neutral and `-1` weaker support. The matrix is
unweighted.

[.pugh-matrix]
[cols="2,1,1,1", options="header"]
|===
| Criterion | Option 1 | Option 2 | Option 3
| No data context for an impermissible combination without the host's own code | +1 | -1 | +1
| Fine-grained rules per entry point | -1 | +1 | +1
| No additional configuration for the host | +1 | 0 | +1
| Stable SPI | +1 | -1 | -1
s| Sum s| +2 s| -1 s| +2
|===

Options 1 and 3 have the same sum. The deciding factor is that #11 requires
rules per entry point and that the SPI can still be changed before the first
release without cost for hosts.

=== Consequences

==== Positive

* An unsuitable combination does not reach the host; it supplies no data for
  it.
* A host distinguishes the three kinds of request with a `switch`; the
  compiler checks that it does not forget one.
* The role configuration of the starter stays the same.

==== Negative

* The SPI change breaks every host that uses `LetterAction.CREATE`.
  Before the first release, this affects only the tests of the library.
* A letter template that is to match several reference types has to exist
  several times.
* The reference type is a free string. A typo when creating a letter template
  only shows up when no preview is produced.

==== Neutral or Follow-Up

* The template administration has to capture the reference type when a letter
  template is created; today nobody supplies which types a host knows. How
  they become available for selection is clarified by the template
  administration as follow-up work. No further mandatory host interface is
  created along the way: QS-007 allows at most three.
* The persistence has to store the reference type.

=== Open Questions

* None. The selection of reference types is follow-up work of the template
  administration (see follow-up work).

=== Review Notes

The owner decided on 2026-11-22 in the review of PR #63:

* ADR-020 and its four relations are accepted. The relation to QS-009 is a
  contribution to access protection, not proof of the checks for download,
  deletion and in the list.
* Permission is checked before the published versions, so that unauthorized
  users do not learn their state. The first draft checked the versions before.
* Exactly one reference type per letter template is sufficient for this state.
