[[adr-007-versionierung-und-unveraenderlichkeit]]
== ADR-007: Versionierte Vorlagen und unveränderliche Schreiben

=== Status

Vorgeschlagen (proposed).

Dieser ADR ist KI-gestützt entstanden. Er gilt erst als Architekturentscheidung,
wenn der verantwortliche Owner ihn geprüft und akzeptiert hat.

=== Entscheidung

Wir schlagen vor:

* Briefpapier und Standardschreiben haben **Versionen** mit Zustand *Entwurf*,
  *veröffentlicht* oder *zurückgezogen*. Veröffentlichte Versionen sind unveränderlich;
  Änderungen erzeugen eine neue Version. Je Vorlage ist höchstens eine Version
  veröffentlicht, die bisherige ist danach *abgelöst*; Nachtrag vom 2026-11-22,
  siehe xref:adr-022-eine-veroeffentlichte-version-je-vorlage[ADR-022].
* Ein **gespeichertes Schreiben** speichert das erzeugte PDF, eine SHA-256-Prüfsumme
  und die IDs der verwendeten Vorlagenversionen. Es wird **nie neu gerendert**.
* Die **Vorschau** erzeugt einen kurzlebigen **Datenstand (Snapshot)**. Speichern
  rendert das PDF aus genau diesem Snapshot, damit das Gespeicherte der Vorschau
  entspricht, auch wenn sich Domänendaten zwischenzeitlich geändert haben.
* Der Snapshot ist an den **Benutzer**, den **fachlichen Bezug** und **beide
  Vorlagenversionen** (Briefpapier und Standardschreiben) gebunden. Beim Speichern
  wird die Erzeugungsberechtigung erneut über den Host geprüft. Eine korrigierte
  Vorlage erfordert eine neue Vorschau.
* Der Snapshot speichert einen **Hash (SHA-256) des formatierten
  Datenkontexts**. Beim Speichern liest die Bibliothek den Datenkontext zusammen
  mit der Berechtigungsprüfung neu und vergleicht den Hash. Weicht er ab, wird
  **nicht gespeichert**. Die Oberfläche meldet die Datenänderung und verlangt
  „Aktualisieren“. Gerendert wird immer aus dem Snapshot.
* Ein Snapshot **läuft nach 30 Minuten ab**. Ein abgelaufener Snapshot wird
  gelöscht. Eine Bereinigung läuft dazu in kurzem Abstand (zum Beispiel jede
  Minute). Bis dahin wird er wie ein nicht vorhandener behandelt. „Aktualisieren“
  oder ein Neuladen erzeugt eine neue Vorschau mit neuem Snapshot. Der ersetzte
  Snapshot wird im selben Schritt gelöscht.
* Das Löschen eines Schreibens entscheidet die `DeletionPolicy` des Hosts (ADR-002).

=== Kontext

Der Owner hat bestätigt: Vorlagen werden versioniert, das gespeicherte PDF bleibt
unverändert. Lösch- und Aufbewahrungsregeln entscheidet die Host-Anwendung.

Zu Snapshot und Datenänderungen hat der Owner am 2026-11-15 bestätigt
(Q-PO-011): Das gespeicherte Schreiben entspricht genau der Vorschau. Geänderte
Daten werden erkannt und erzwingen ein Aktualisieren. Die Ablaufzeit beträgt
30 Minuten. Abgelaufene und ersetzte Snapshots werden sofort gelöscht.

=== Entscheidungstreiber

* Nachvollziehbarkeit: Was der Benutzer gesehen hat, wird gespeichert.
* Unveränderlichkeit gespeicherter Schreiben.
* Einfaches Modell für Fachanwender (Entwurf, veröffentlicht).

=== Betrachtete Optionen

==== Option 1: Versionierte Vorlagen, PDF unverändert, Speichern aus Vorschau-Snapshot

Gespeichertes entspricht exakt der Vorschau. Snapshot muss kurzzeitig gehalten werden.

==== Option 2: Versionierte Vorlagen, Speichern liest Daten neu

Kein Snapshot nötig. Gespeichertes kann von der Vorschau abweichen.

==== Option 3: Keine Versionierung, PDF unverändert

Einfach, aber nicht nachvollziehbar, mit welcher Vorlage ein Schreiben entstand;
laufende Bearbeitung beeinflusst Vorschauen anderer Benutzer.

=== Pugh-Matrix

`+1` steht für bessere Unterstützung, `0` für neutral, `-1` für schwächere
Unterstützung und `?` für eine Bewertung, die eine menschliche Prüfung oder
einen Prototyp braucht. Enthält eine Spalte ein `?`, ist ihre Summe ebenfalls `?`.

=== Konsequenzen

==== Positiv

* Gespeicherte Schreiben sind revisionssicher nachvollziehbar.

==== Negativ

* Snapshot-Verwaltung (Ablaufzeit, Speicherort, Bereinigung) ist zusätzlicher Aufwand.
* Beim Speichern ist ein zusätzlicher Aufruf beim Host nötig, um den Datenkontext neu zu lesen.
* Ändern sich Daten häufig, muss der Benutzer öfter aktualisieren.

==== Neutral oder Folgearbeiten

* Laufzeitsicht um den Fehlerfall „Daten geändert“ ergänzen (erledigt).
