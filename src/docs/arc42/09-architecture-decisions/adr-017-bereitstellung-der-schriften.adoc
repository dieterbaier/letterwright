== ADR-017: Providing the fonts for preview and PDF

=== Status

Accepted on 2026-11-19.

This ADR was written with AI assistance. The owner checked and accepted it in
the review of PR #40.

=== Decision

The fonts come from a folder of the host, with free substitute fonts (Option 3):

* **No fonts that require a license in the library.** Maven artifacts and the
  npm package contain only fonts under free licenses that allow redistribution,
  embedding in the PDF and delivery to the browser.
* **The host provides fonts.** It configures a folder from which the library
  reads font files (TrueType or OpenType). The folder is the only source:
  letterheads do not upload fonts, and there is no interface in `spi` for it.
  The host is responsible for the license for server use, embedding in the PDF
  and delivery as a web font.
* **No system fonts.** The library does not rely on fonts being installed on
  the host's target system or in the user's browser.
* **Resolution in a fixed order**, the same for preview and PDF:
  . Font with this family name in the host's folder.
  . Otherwise the free substitute font from the library's mapping table.
  . Otherwise the library's free default font.
+
Both engines load the resolved file: openhtmltopdf embeds it in the PDF,
Paged.js loads it via `@font-face` from the library's backend (ADR-004, ADR-014).
* **Substitute fonts preserve the typeface.** The mapping table lists only free
  fonts. Where an OFL font with the same character widths exists (metrically
  compatible), it is used, so that line and page breaks stay the same.
  Otherwise an OFL font without the same character widths is used that comes
  as close as possible to the look of the original font.
* **Notice in the administration.** If a letterhead or a letter template uses a
  font that is missing in the host's folder, the administration shows a notice
  with the substitute font used instead. The notice does not block. Generating
  letters continues with the substitute font.
Mapping for the fonts of the sample DOCX. The prototype checks the candidates
whose license has not been checked:

[cols="1,1,2", options="header"]
|===
| Font in the specification | Substitute font | Note
| Arial | Liberation Sans | SIL OFL 1.1, same character widths
| Arial Narrow | PT Sans Narrow | SIL OFL 1.1, without the same character widths; chosen by the prototype, see result. Liberation Sans Narrow (GPLv2 with exceptions, no longer part of Liberation 2.x) is not used.
| Times New Roman | Liberation Serif | SIL OFL 1.1, same character widths; only the fallback value of the DOCX
| Courier New | Liberation Mono | SIL OFL 1.1, same character widths; only declared
| Calibri, Cambria | Carlito, Caladea | Check the license in the prototype; only theme fonts of the DOCX
| Segoe UI Symbol, MS Gothic (box ☐) | free font with U+2610 | Candidate Noto Sans Symbols 2 or DejaVu Sans; only for the box in `Formular_intern.docx`
|===

=== Context

For visible text, the sample DOCX files in `src/examples/` use only Arial and
Arial Narrow (`Geschaeftsbrief.docx`), and Arial plus Segoe UI Symbol or
MS Gothic for the box ☐ (`Formular_intern.docx`). Determined from
`document.xml`, headers and footers and the styles including inheritance, not
only from the font table. None of the DOCX files embeds fonts.

Arial and Arial Narrow belong to Monotype. The copies shipped with operating
systems do allow embedding in documents in their file. A right to use them on
a server or to deliver them to browsers does not follow from that. The library
is MIT-licensed and distributed through GitHub Packages (ADR-012). It cannot
ship such fonts.

So far, ADR-004 provides that font files belong to the letterhead and are
uploaded by the template manager. The deployment view says the same. The owner
decided on 2026-11-19: the host provides the fonts, through a configurable
folder, and the library uses free substitute fonts when a font is missing. How
DOCX specifications are imported is still open (ADR-003). The notice about
missing fonts therefore belongs in the administration, wherever the letterhead
is created.

=== Decision Drivers

* **License responsibility with the operator:** Whoever uses a font that
  requires a license owns the license and provides the file.
* **Independence from the target system:** The result does not depend on which
  fonts are installed on the server or in the browser.
* **Rendering fidelity (QS-004):** Preview and PDF use the same file.
* **Style fidelity (QS-013):** The typeface of the specification is preserved,
  even with a substitute font.
* **Maintenance effort for business users:** Whoever maintains a letterhead
  does not have to obtain font files.
* **Operating effort for the host:** As little additional configuration and
  provisioning per environment as possible.

=== Considered Options

==== Option 1: Upload fonts as part of the letterhead

Current state in ADR-004. The template manager uploads the font files with the
letterhead; they are stored in the host's database. No configuration in
operation, fonts move with the data through the environments. But a business
user has to obtain font files and in effect decides on their license, and the
same font is stored several times in the database, once per letterhead.

==== Option 2: System fonts of the target system

The engines use installed fonts. No effort in the library. The server (often a
slim Linux container) usually does not have Arial, and the user's browser has
different fonts than the server. Preview and PDF can therefore differ without
anyone noticing.

==== Option 3: Font folder of the host with free substitute fonts (chosen)

The host configures a folder with licensed fonts. The library ships free
substitute fonts, with the same character widths where possible, and points
out missing fonts in the administration. The host has to fill the folder in
every environment, for example in the container image or through a volume.

=== Pugh Matrix

`+1` means better support, `0` neutral, `-1` weaker support, and `?` a rating
that needs a human check or a prototype. If a column contains a `?`, its sum is
also `?`. The matrix is unweighted.

[.pugh-matrix]
[cols="2,1,1,1", options="header"]
|===
| Criterion | Option 1 | Option 2 | Option 3
| License responsibility with the operator | -1 | 0 | +1
| Independence from the target system | +1 | -1 | +1
| Rendering fidelity (QS-004) | +1 | -1 | +1
| Style fidelity (QS-013) | +1 | -1 | ?
| Maintenance effort for business users | -1 | +1 | +1
| Operating effort for the host | +1 | 0 | -1
s| Sum s| +2 s| -2 s| ?
|===

For style fidelity, Option 3 gets `?`: with the original fonts in the folder,
it is equivalent to Option 1. Without them, the result depends on how well the
substitute font matches, and the prototype has to show that, above all for
Arial Narrow. The substitute fonts themselves could be combined with any
option. The matrix compares the source of the original fonts.

Without style fidelity, Option 3 reaches +3. Even with `-1` for style fidelity,
it would be level with Option 1 at +2. Option 1 pays for its lead in operating
effort with the license question for the business user.

=== Consequences

==== Positive

* The library stays freely redistributable. No font license is attached to its
  release.
* Preview and PDF use the same file, independent of server and browser.
* Without configuration, the library runs with substitute fonts. That is enough
  for the sample application and for tests.
* Business users see in the administration when a letter is not generated with
  the original font.

==== Negative

* The host has to provide the font folder in every environment. If it is
  missing in an environment, that environment generates letters with a
  substitute font. This is only noticed through the notice in the
  administration.
* A substitute font is never identical. For Arial Narrow there is no OFL font
  with the same character widths. Without the original font in the folder, line
  and page breaks can shift there compared with the specification.
* A PDF that was generated with a substitute font and stored stays that way.
  The immutability of stored letters (ADR-007) applies here too.
* The library needs a mapping table and resolution by family name, both with
  tests.

==== Neutral or Follow-Up

* ADR-004 and the deployment view are aligned with issue #39.
* The prototype (#3) checks both paths separately: reference fonts from the
  host load in the sandboxed iframe under CSP, are embedded in the PDF and are
  licensed for both uses; the substitute fonts are measured against QS-004 and
  QS-013 (ADR-004).
* Implementing the font folder in the rendering pipeline (Epic #7). The
  implementation determines the name and form of the configuration, for example
  a Spring property in the starter.
* Notice about missing fonts in the administration: #41 (Epic #8, also affects
  Epic #9).
* The library must name the licenses of the bundled substitute fonts in its
  license documentation.


=== Prototype Result

The throwaway prototype from #3 (`prototyp/README.adoc`) checked both paths with
`Geschaeftsbrief.docx`.

* *Host's folder:* Family, weight and style come from the font file, not from
  the file name. No system fonts, no fonts in the repository. Arial and Arial
  Narrow load in the sandboxed iframe under the CSP and are embedded in the PDF.
  Clearance of their license for embedding and web font use is pending.
* *Resolution:* host's folder, then mapping table, then default font Liberation
  Sans. The substitute font is registered under the family name of the
  template, the CSS stays the same, and PDF and preview get the same file. Each
  replaced family produces a notice.
* *Arial → Liberation Sans 2.1.5:* same character widths, as assumed.
* *Arial Narrow → PT Sans Narrow:* There is no OFL font with the same character
  widths. Compared were Encode Sans Condensed, Fira Sans Condensed, IBM Plex Sans
  Condensed and PT Sans Narrow. Wider fonts wrap in the fixed-width columns;
  with Encode Sans Condensed the info block moves 4.2 mm lower. PT Sans Narrow
  is 6 to 7 % narrower and looks softer, but keeps all breaks. The line starts
  are at most 0.1 mm off from Word. The central department decides whether the
  look is good enough (QS-013).
* Both reference letters remain PDF/A-2b and PDF/UA-1 with substitute fonts.
* *Ligatures:* PDFBox 3 writes the fi ligature of PT Sans Narrow as U+FB01 into
  the text of the PDF. Depending on the viewer, search and copy return “ﬁ”. The
  remedy for the product is open: switch off ligatures when embedding, or ship
  the substitute font without `liga`; under the OFL the latter requires a new
  name.
* *Variable fonts* (for example Archivo Narrow, Roboto Condensed) are not
  embedded reliably by PDFBox. The mapping table lists only static fonts.
* A script with a fixed version and checksum loads the substitute fonts; they
  are not checked in.

Not checked: Carlito, Caladea, the candidates for the box, and Liberation Serif
and Mono. The business letter does not need them. Also not checked: whether the
browser falls back to a system font for missing characters.

=== Assumptions

* License of the original fonts (owner, 2026-11-21): The library ships them
  neither in the repository nor in artifacts or tests. If the host provides
  them, the PDF embeds subsets of them (PDF/A requires this), and the preview
  receives them as a web font. The project assumes that the host is allowed to
  do both; its license is what counts.
* The library recognizes a font by the family name from the font file, not by
  the file name. Styles (bold, italic) are separate files in the folder.
* openhtmltopdf and Paged.js set the same TrueType or OpenType file with the
  same character widths. The prototype checks this.
* The browser does not fall back to installed fonts, because the preview uses
  only fonts that come from the backend via `@font-face`. For characters that
  none of these fonts contains, the browser can still take a system font. The
  prototype checks this as well.

=== Open Questions

The owner decided in the review of PR #40:

* *Substitute for Arial Narrow:* as with the other fonts, an OFL font, here
  without the same character widths.
* *Further font source:* No. The host's folder is the only source.
* *Folder or interface:* The folder is enough.

It remains open whether the library additionally logs missing fonts at startup
or during generation. The question is in #41.
