Die Vorschau nimmt die neuesten veröffentlichten Versionen von Standardschreiben
und Briefpapier. Passt der Bezugstyp nicht, fragt die Bibliothek den Host gar
nicht. Ob es veröffentlichte Versionen gibt, prüft sie erst mit der Berechtigung;
ein Unberechtigter bekommt immer „nicht erlaubt“. Ohne Berechtigung oder ohne
veröffentlichte Version fragt sie den Host nicht nach dem Datenkontext
(xref:adr-020-zulaessige-kombination-aus-standardschreiben-und-bezug[ADR-020]).
Eine aktualisierte Vorschau legt einen neuen Snapshot an, dessen 30 Minuten neu
beginnen, und löscht den bisherigen, wenn er dem Benutzer gehört. Einen fremden
oder unbekannten bisherigen Snapshot übergeht sie, als wäre keiner angegeben. Das
Verhalten ist in `features/schreiben/vorschau-erzeugen.feature` spezifiziert.

Der Snapshot ist an den angemeldeten Benutzer, den fachlichen Bezug und beide
Vorlagenversionen (Briefpapier und Standardschreiben) gebunden. Beim Speichern prüft
die Bibliothek die Erzeugungsberechtigung **erneut** über den Host. Wurde die
Berechtigung nach der Vorschau entzogen, wird nicht gespeichert. Ein Snapshot eines
anderen Benutzers wird wie ein nicht vorhandener behandelt (404).

Zu einem Snapshot gibt es höchstens ein Schreiben
(xref:adr-021-hoechstens-ein-schreiben-je-snapshot[ADR-021]). Speichert der
Benutzer dieselbe Vorschau erneut, etwa nach einem Doppelklick oder weil die
Antwort verloren ging, bekommt er das schon gespeicherte Schreiben zurück, ohne
dass ein weiteres PDF entsteht. Speichern zwei Anfragen gleichzeitig, setzt die
Persistenz die Eindeutigkeit durch; die unterlegene Anfrage entfernt ihr
abgelegtes PDF und bekommt das Schreiben der anderen. Ein neues Schreiben
entsteht nur aus einer neuen Vorschau. Hat sich der Datenkontext geändert,
entsteht kein PDF; der Snapshot bleibt, bis eine neue Vorschau ihn ersetzt oder
er abläuft. Ein nicht konformes oder nicht prüfbares PDF wird nicht gespeichert
(fail-closed). Das Verhalten ist in
`features/schreiben/schreiben-speichern.feature` spezifiziert.

== Gespeichertes Schreiben drucken

Gedruckt wird nur ein gespeichertes Schreiben (Q-PO-002). Die Vorschau bietet
kein „Drucken“ an.

[plantuml,laufzeit-drucken,svg]
----

actor Sachbearbeiter as SB
participant "Übersicht (React)" as UI
participant "adapter-web" as Web
participant "usecases-service" as App
participant "Browser: Druckfunktion" as Druck
SB -> UI: Drucken (gespeichertes Schreiben)
UI -> Web: GET /schreiben/{id}/pdf
Web -> App: Schreiben abrufen ({id})
App -> App: Berechtigung prüfen (Host)
App --> Web: PDF (unverändert)
Web --> UI: 200, PDF
UI -> Druck: PDF an die Druckfunktion des Browsers übergeben
@enduml
----

Gedruckt wird dasselbe unveränderte PDF wie beim Download. Druckt ein Benutzer
die Vorschau über die Druckfunktion des Browsers, verhindert die Bibliothek das
nicht. Für dieses Ergebnis ist sie aber nicht verantwortlich.

== Fehlerfall: Berechtigung beim Speichern entzogen

Lehnt der Host beim Speichern ab, wird nichts erzeugt und nichts persistiert. Der
Snapshot wird verworfen. Die Antwort verrät keine Inhalte des Snapshots.

== Fehlerfall: PDF nicht konform, Rendering schlägt fehl oder Prüfung nicht ausführbar

Schlägt die PDF-Erzeugung fehl, ist das PDF nicht konform oder lässt sich die
Konformitätsprüfung nicht ausführen (Fehler, Zeitüberschreitung), wird **nichts
persistiert** (fail-closed, siehe
xref:adr-005-pdfa-und-barrierefreiheit[ADR-005]). Der Benutzer erhält eine
verständliche Meldung. Der Fehler wird mit Vorlagenversionen und Korrelations-ID
protokolliert, ohne personenbezogene Inhalte.

* Liegt die Ursache in der Vorlage, muss der Vorlagenverwalter eine **neue
  Vorlagenversion** veröffentlichen. Der alte Snapshot bleibt an die fehlerhafte
  Version gebunden; der Benutzer braucht eine **neue Vorschau** mit der korrigierten
  Version.
* Bei einem vorübergehenden technischen Fehler (z. B. Zeitüberschreitung) kann der
  Benutzer das Speichern mit demselben Snapshot wiederholen, solange er nicht
  abgelaufen ist.

== Fehlerfall: Daten seit der Vorschau geändert

Weicht der Hash des neu gelesenen Datenkontexts vom Hash im Snapshot ab, wird
nichts erzeugt und nichts persistiert. Die Oberfläche meldet, dass sich die Daten
geändert haben, und verlangt „Aktualisieren“. Das erzeugt eine neue Vorschau mit
neuem Snapshot. Der alte Snapshot wird dabei gelöscht
(xref:adr-007-versionierung-und-unveraenderlichkeit[ADR-007]).

== Fehlerfall: Snapshot abgelaufen

Ein Snapshot läuft 30 Minuten nach der Vorschau ab und wird gelöscht. Ist er beim
Speichern abgelaufen, lehnt die Bibliothek das Speichern ab und fordert eine neue
Vorschau an, statt mit neu gelesenen Daten zu speichern. Ein Neuladen der Vorschau
erzeugt einen neuen Snapshot
(xref:adr-007-versionierung-und-unveraenderlichkeit[ADR-007]).
