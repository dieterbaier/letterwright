= Frontend of letterwright

npm workspace with the package of React components (ADR-001, ADR-009).

== Packages

`packages/components`:: `@dieterbaier/letterwright`, the React components for
embedding in a host application. React is a peer dependency. The host imports the
stylesheet separately: `@dieterbaier/letterwright/styles.css`.

== Commands

In the directory `src/application/frontend/`, with Node.js 22.22.2 or newer on the
22 line, 24.15 or newer on the 24 line, or 26 and later. jsdom and Vitest require
these ranges. `.npmrc` sets `engine-strict`, so `npm ci` stops right away with
another version.

[source,sh]
----
npm ci          # install dependencies from package-lock.json
npm run lint    # ESLint and type check
npm run build   # library and type declarations to dist/
npm test        # Vitest with coverage gate
----

== Styling (ADR-013)

* UnoCSS with the class prefix `lw-`. Classes without the prefix generate no CSS.
* No global reset (no preflights).
* All styles live in the CSS layer `letterwright`. Host styles outside this layer
  take precedence without `!important`.

`src/test/styling.test.ts` checks these three rules against the UnoCSS configuration.

== Test conventions (ADR-010, ADR-011)

* Tests live next to the code as `*.test.ts` or `*.test.tsx` and run with Vitest,
  React Testing Library and jsdom.
* Coverage with the V8 provider: at least 80 % of lines and branches. Below that,
  `npm test` fails. Test helpers under `src/test/` do not count.
* Every component test checks the rendered markup with
  `checkAccessibility(container)` from `src/test/axe.ts`. Violations of impact
  "serious" and "critical" fail the test.
* axe cannot evaluate colour contrast in jsdom. It needs a check in a real
  browser. The notice "HTMLCanvasElement's getContext()" in the test output comes
  from that and is not an error.
